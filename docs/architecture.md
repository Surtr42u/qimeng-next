# 架构

## 唯一业务权威

同一 Go 模块化单体可运行在 PC/NAS，用户也明确保留 Android 离线本机模式。Android 的独立 embedded runtime 只负责服务启动、应用私有存储授权和媒体工具适配；界面仍经正式 API 连接所选实例。业务核心、独立服务构建与 PC/NAS 测试不依赖 Android，移除 embedded runtime 不改领域用例。连接远程实例与本机实例的队列、凭据和缓存按实例身份隔离，没有客户端第二套业务数据库或自动日常双向备份合并。

SQLite 位于服务本地磁盘。单服务排他锁、SQLite WAL、外键、FULL 同步及版本化迁移组成持久化基础。数据库迁移按文件顺序执行并保存 SHA-256，已应用迁移变化或未知新版本会拒绝启动。领域公式与编号函数不依赖 IO，HTTP 适配不拥有业务规则。

原件位置与 SQLite 控制根分离。运维通过 `QIMENG_STORAGE_ROOTS` 配置可信逻辑根，库注册只引用逻辑 ID 与相对目录，模型没有任意本机路径权限。已有 NAS 目录可原地注册；库根不能重叠。上传暂存、回收站、替换旧版和解码快照落在对应库的内部目录，保持同一文件系统上的无覆盖发布；数据库快照与最终衍生缓存仍在控制根。缺失挂载不回退成空库。

本人UI仍可输入和查看绝对库根，由仅管理员可用的解析/回显接口桥接上述逻辑位置，不扩张存储权限，也不把路径暴露给一般查询或MCP。DNS-SD仅在命令入口作为可选宿主能力发布候选；关闭发现或剥离Android本机模块都不改变业务协议和数据库。

## Next 原生数据与恢复

同一个资产 ID 表示一个受管理的条目。资产有一组内容版本和一个当前文件位置。明确替换原件会新增版本，改名或移动只变更位置。哈希相同可以形成候选，两个资产是否合并取决于明确的业务操作。下表给出本轮原生改造的所有权，实际落库及平台验收按[当前状态](status.md)记录。

| 业务事实 | 权威写入入口 | 中断或重试后的依据 |
|---|---|---|
| 原件版本与当前位置 | Go 上传发布、扫描、明确替换或移动，校验资产 ID、版本、目标库与路径 | 先落持久文件意图，再核对原件身份、大小、摘要与目录占用，最后提交业务记录与回执 |
| 版本对应的续播和时间轴 | 播放事件更新该资产、该内容版本的续播行；标记操作引用创建标记时的版本 | 事件 ID 去重，旧版本的事件和标记仍可追溯；播放新版本前核对版本号 |
| 收藏、日赞、标签、作者与角色关系 | 每个操作只提交自己拥有的事实。人工确认、清空和解除分别保留；候选随证据保存，确认后才进入正式关系 | 重读当前值与相关修订。收藏和日赞各有独立回执。复扫与 AI 建议保留人工决定 |
| 命名及集合成员 | Go 按目标目录和命名族分配编号，组图页及短剧集序绑定集合成员 | 计划记录该次操作所用的目录、对象和输入摘要，发布时再核对实际目标，逐项回读成功回执 |
| 整库恢复与跨实例交付 | 整库使用一致 SQLite 快照与原件清单；选择性交付使用独立版本的 Next 原生包，在接收实例按授权应用 | 整库在空目录逐项核对摘要。设备在包与条目层按来源实例、稳定 ID 和修订回读处理结果；手机在线连接 NAS 时直接调用 NAS API |

数据库迁移版本、整个备份归档的格式版本和设备结果包的格式版本独立演进。旧版 qimeng-media 提供已确认的产品行为参考。旧 v2 资料的兼容与一次性导入不属于 Next 原生协议和发布条件。已经存在于 Next 数据库的记录按已发布迁移继续演进。

## 模块边界与实际调用

| 责任 | 允许的调用与约束 |
|---|---|
| Go 命令入口 | `cmd/qimeng` 装配配置、实例和服务。独立的 `cmd/qimeng-backup` 负责离线备份工具 |
| HTTP 与业务用例 | `internal/httpapi.API` 实现由 OpenAPI 生成的 Go `ServerInterface`。服务使用生成的标准库路由挂载业务端点。认证、结构校验和协议编码位于该层；业务权限、幂等回执与事务提交由 `service` 负责。健康检查和静态 Web 由宿主挂载 |
| 收藏与当日点赞 | `internal/engagement` 只接收已获授权的事务、当前资产与服务时间，更新该意图负责的字段或当天记录。它只引用 `model` 和 `store`。Web 和 Android 提交用户点击的那一个开关，状态、累计数与历史均从 Go 回读 |
| 上传内容核验 | `internal/mediafile` 从传入的文件流检验媒体容器、长度与 SHA-256，支持调用者取消读取。该包不依赖其他业务包。授权、内容版本、命名与目标占用复核、持久化发布意图及最终事务都由 `service` 负责 |
| 规则与业务记录 | `domain`、`analytics`、`authorlist`、`sourcerules`、`migration`、`model` 接收已经提供的数据。当前时间、文件内容、数据库查询和网络响应由调用方或适配器提供 |
| 存储与外部环境 | `store` 持有 SQLite 迁移和持久化原语。`storage`、`backup` 和 `sysmon` 分别处理主机文件、备份与系统读数。服务组合这些能力并决定一次业务写入的边界 |
| Web、桌面与 Android | Web 页面通过数据层读写，桌面壳负责窗口与服务器连接。Android 页面使用 ViewModel、Repository 和 SDK。本机宿主经运行接口启动同一 Go 服务 |
| 外部 AI | MCP 执行器保存受托凭据、调用正式 API、返回可接续的结果。命名、冲突处理和是否准许业务写入均由 Go 决定 |

以「追加同作品下一张图」为例，页面或 MCP 把作品和目标库交给命名接口。Go 用例读取授权库的现状，调用纯编号规则，提交时再核对目录和修订。界面只展示预览与实际回执。变更续号时应从同一规则及其消费点着手。[编号实现](../server/internal/domain/naming.go) · [命名用例](../server/internal/service/naming.go)

Go 的具体包引用由[依赖检查](../server/internal/architecture/boundaries_test.go)约束。检查解析生产源码的真实 import，也覆盖非当前操作系统的源文件。新增顶层模块时一起明确所有权和允许的引用。Web 与 Android 的具体约束分别维护在[Web](../web/README.md)和[Android](../android/README.md)。跨对象的事务范围、调用时序和用户意图仍需结合真实入口评审。

### 当前有效的取舍

| 选择 | 依据、代价与复查条件 |
|---|---|
| 一个 Go 服务持有库写入权 | 编号、权限、文件发布和回执可以在同一实例核对。写入会竞争同一协调锁。若实际大批量任务拖慢交互写入，先量锁等待和磁盘耗时，再决定是否缩小临界区。[业务写入入口](../server/internal/service/service.go) |
| Android 的本机宿主独立于普通客户端 | 手机离线时仍使用同一 API。代价是两种 APK 和额外的原生打包验证。退役本机能力前需验证手机独有资料迁出、纯客户端连接目标实例以及独立服务的发布。[运行边界与剥离条件](runtime-separation.md) |
| OpenAPI 是跨端协议正文 | 多语言客户端可以追溯到同一输入。代价是改字段后必须重新生成、更新锁并核对各端兼容性。生成器或模板升级需查看实际签名差异。[协议](../api/openapi.yaml) · [固定生成流程](../tools/generate_sdks.py) · [SDK 来源锁](../api/sdk.lock) |

## 身份与修订

资产 ID 与文件名、相对路径及哈希独立。资产 `revision`、标签集合 `tagsRevision`、作者关系 `authorsRevision` 与文件 `contentVersion` 表达不同变化。作者是独立身份，资产关系为多对多；`authorId` 仅是兼容主显示字段。常规与 COS 作者身份不合并，但 COS 文件允许附普通作者；浏览分区按是否存在 COS 作者关联判断。“其他搁置”是未知占位，关联真实作者后自动去除占位，不触发后台研究。

人工元数据修改标记 `metadataSource=human`。接收批次 AI 凭据只能处理本批未入库输入，不能调用既有资产修改接口，因此迟到研究不能反盖人工修正。作者资料维护使用另一种明确任务：绑定作者 ID、基础修订、授权字段、允许清空、有效期与写入次数；与接收批次凭据互斥，不能换成管理员权限。标签整体替换含明确空集合，检查标签修订；读旧列表的客户端不能覆盖新修改。收藏与关注是布尔，点赞以服务端自然日去重并累计。

原作/出处与角色分别有稳定 ID、别名和修订，角色关联所属原作；资产保存关系集合，展示名从当前词表读取。`acquisitionSources` 单独保存用户填写的获取渠道，不与作品出处、作者主页或研究证据混用。全局标签删除同时移除关系并推进受影响资产的标签修订，旧表单不能恢复已移除项。作者删除保留媒体与其他作者；明确合并保留目标人工档案，源冲突资料保存在归档中。

作者 TXT 声明绑定稳定作者 ID。编号清单保留别名、获取渠道与作品行，同一作者跨片段匹配取并集。纯姓名清单仅建立或复用身份。人工选择和解除分别记录，并把当前文件名写入所属片段。重导时返回缺失的人工挂靠项，由管理者选择保留或移除。上传、扫描、移动和恢复都使用同一匹配规则，明确选择的常规作者可追加获取渠道。按名创建和整体替换作者集共同检查资产修订、作者修订及幂等键，在一个事务提交。

作者镜像默认关闭。管理员可选单片段或合成总表，写入已授权外部存储根内的 TXT。变更在事务内标记待发布，后台从一致快照生成，状态可回读。正文变化时保留上一代与独立 SHA-256。目录采用 `当前/上次` 或 `current/previous` 时分代保存，平铺目录下保留三份。外部编辑冲突保留现场，镜像错误独立于业务提交。完整备份恢复保留 TXT 与人工决定，新的实例须重新配置镜像目的地。

标签墓碑也约束原本未关联该词的资产：旧候选不能通过另一个资产的 PUT 将删除词自动建回。只有显式创建词条才恢复词表身份并推进修订；数据库触发器拒绝把关系挂到删除状态的词条。

组图和 AI 短剧有稳定集合身份。图片仍逐张显示；组图页码与作品号分离。Go 根据目录、family、图片/视频类别分配最小空号，扩展名不另分序，动图归图片。组内页码固定半角括号，已有组图补页从最大页码加一，不补洞或重排。短剧用集合 ID 与服务端序号追加，保留用户原始备注，不自动研究视频备注。

COS 目录作品是另一种稳定实体，绑定库、目录与目录作者，不借用组图或短剧集合。扫描、显式选取作品上传和跨目录移动共用同一归属用例；文件意图保存待新增的目录作者/作品，业务提交和这些身份在同一事务入账。目录派生作者单独记录，移动时保留其他明确的作者关系，不把普通备注修改误当作禁止目录对账。

媒体列表、计数、历史与分面共享筛选谓词和搜索纯函数；数字按完整数字段匹配，括号页码与裸编号分开。同维多选 OR、跨维 AND；相册混合行使用后端提供的 opaque key，常规出处与 COS 作者同一行仍保持 OR。稳定复合键游标绑定全部筛选与排序，COUNT 与本页在同一只读快照内完成；旧 offset 不再用于资产、作者和历史。默认列表按文件日期，未知日期排后；真实收藏时间只在未收藏到收藏的变化时写入。

## 接收、计划与提交

接收批次为每个输入分配稳定上传 ID。普通上传 complete 即正式入库，不依赖 AI；智能上传 complete 仅表示接收完整，后续状态独立。上传会话、偏移、摘要、来源时间、原名、相对目录和结果保存在数据库。

AI 写凭据绑定一个批次及明确 scope。默认 AI 配置仅 `read`；可信执行器需由管理员签发本批 `ingest/research/organize` 凭据。管理员替换与永久删除不出现在 AI 工具目录。新作者创建受本批范围与输入数约束；已有资料修改仍属于管理员。

研究候选保存来源、证据、输入摘要和研究预算消耗，不直接修改已确认归属。批次保存额度、修订和停止状态；同一失败方法无进展重复会明确拒绝。服务端只控制已提交研究记录与业务权限，外部模型请求、网络外传及实际费用必须由可信执行器执行限额，不能声称任意模型消费均由服务端限制。

计划是服务端持久对象，具有完整输入清单、目标名称、作者集合、集合页序、摘要和命名空间指纹。提交使用原计划 ID 与摘要；不从截断预览重建。每项单独事务提交与回读，已成功项不会因其他项失败或通知失败重新入库。当前批次外的新增、人工编辑或命名空间变化会导致剩余计划冲突；已提交结果保留。

## 文件一致性

库列表在同一只读快照返回登记总数、每库未进回收站的文件数和最近扫描状态。目录树分页按名字定位，节点计数只含直接子文件。注销库需要当前库修订，未完成上传、扫描、文件发布、有效来源回收许可及未处置的回收站项目会返回具体冲突。注销事务清理资产索引、词表关联及统计物化，磁盘原件、历史事件、TXT 声明和接收回执均保留。取消或重复上传仍有已接收字节时，原存储绑定仅用于读取该前缀进行备份。同一目录可重新登记为新库，跨实例恢复不会重新挂载旧根。

手动扫描遍历整库。每次按目录读取最多 128 个条目，一次查询这些路径已登记的大小、时间和 COS 归属。普通文件的大小和修改时间均未改变时可跳过内容读取。已有媒体的写通知会复核内容摘要。新增和改变的图片在入库前取得内容摘要和图片头信息。

普通库中首次发现的小图先在写锁外完成读取，随后分批短时持锁。每个文件在提交前重验文件身份、大小、修改时间、当前索引及待发布操作。业务字段和进度随同一事务提交。已占用路径、可能移动的文件与待发布冲突沿用逐项核对。缺失对账按已索引的父目录进行，能够覆盖磁盘上已消失的整个子树。对可能缺失的条目，先重新确认当前资产仍指向该路径，再检查原件。缺失原件保留历史，目录读取错误单独报告。[旧版方法、实际代价与验收结果](verification.md#手动扫描逐段核对)

文件意图持久记录源文件对象身份。清理旧名之前复核发布目标及原件，目标丢失时从仍存在的已核验硬链接恢复。旧名或新名指向内容相同的另一文件时保留双方。文件操作待提交期间，其他写入不能改动同一资产的人工字段；扫描同时避开未决的新旧路径。批次部分成功的回执可用同一键继续推进。已发布的计划项保留当时的作者集合、内容版本和作者修订，隔离恢复后也能核对清单或目录补入的作者。

整批取消在同一事务中关闭未发送、接收中和已暂存的输入，释放上传名额和未传字节的预留。已收字节、原始选择、重复项及已发布的资产版本继续可查。批次有文件正在发布时，须先恢复该发布再取消其余输入。升级会核对历史取消记录并释放其遗留的预留。

隔离恢复将旧实例的作品维护任务标记为已撤销，保留任务的资产身份、当时版本、已用额度与研究依据。管理员仍可查历史，生成新的研究材料、补资料或改名需要当前实例的新任务。

服务器目录投放是可选接收适配器。两轮观测文件身份、修改与变动时间和长度，流式复制前计算摘要，提交前再次核对来源。普通接收用例执行原有空间、类型、分片和冲突校验。根级 TXT 使用同一清单事务，在缺少人工作品时保留它们。来源路径与已处理的文件版本持久绑定；进程重启继续同一上传进度。成功后媒体与 TXT 都保留在原目录。完整的独立保护和可信来源回执属于另一个流程。

在大小写不敏感的媒体盘上，把 `example.png` 改成 `Example.png` 前，服务核对父目录中的实际目录项。若两个名称指向同一项，先在该卷保存可恢复的硬链接，再按目标拼写发布，数据库提交后释放临时链接。若目标已经是另一项，服务保留两项并返回冲突。该规则也用于启动时恢复已中断的改名。

输入路径仅接受受控相对路径；拒绝穿越、不合法字符、坏编码和链接。Go `os.Root` 限制文件操作在根内，受管目录由服务拥有。数据根内的管理员外部写入仍属于运维例外，不能等同通过正式 API 的并发保证。

文件与 SQLite 不能共享物理事务，服务采用显式文件意图：先持久化输入、目标、版本和回执身份；无覆盖发布并核验原件；同一数据库事务提交业务状态与幂等回执；最后清理临时源或已授权旧版。启动重放同一意图，不换资产身份。冲突保留文件供核对。

替换仅接受管理员指定资产及预期内容版本；新文件验证后才处理旧版，保留业务关系与事件。删除先进入服务回收站，恢复同一资产及关系；永久删除是回收站中的独立管理操作。源文件清理与旧版清理分离。

内容读取在短锁内打开对应版本的文件句柄。Linux 和 Android 的缩略图与研究预览持有同一个可寻址文件描述符，并把它传给 FFmpeg 或 ffprobe。即使原路径被替换，解码器仍读取选中的文件对象，大视频无需另存副本。Windows 使用同卷的临时硬链接，完成后清理。视频时间轴标记保存独立身份、修订、颜色和内容版本，替换后保留原标记及其版本。

## 备份与迁移边界

备份接口先产生一致性 SQLite 检查点，再由单个有界后台导出用例生成完整 `.qnext`。每个载荷绑定快照内的身份、内容版本、长度与摘要；当前文件在打开前已替换或读取中变化会失败。网络中断不停止已接收的导出任务；进程中断将状态标为 interrupted，已发布但未回执的归档重新完整校验后采用。未完成上传按快照内已提交 offset 保留前缀，不把尚未提交的磁盘尾部当作接收事实。

`internal/backup` 负责顺序容器与摘要，服务用例负责快照覆盖、权限、进度与文件解析。独立 `qimeng-backup` 命令将恢复落到新隔离目录，先检验迁移校验和及真实 SQLite 结构，拒绝额外触发器/视图；逐项验证后才发布数据库。外部存储根不会从备份自动激活；新实例身份和运行凭据分离于被保留的业务身份。历史备份报告保留且标记其快照未随本次归档递归复制。

批次保护单独保存清单指纹、全量原输入去向、快照摘要及每个成功输入的内容版本。可信配置的目标使用内容地址对象和快照对象，复制后重开读回校验，最后无覆盖发布证据对象；中断重试只复核同一对象，不采用新版文件。服务比较目标与业务/原件卷身份；运维仍须明确独立物理故障域，不能用不同目录、RAID 或卷名代替硬件验收。

每次上传在发布事务中记录实际入库内容版本。旧上传仅从已提交文件操作或满足原新增/替换版本约束的入库回执回填。独立保护与来源许可同时核对原输入、上传版本、当前原件身份、版本和摘要；换回相同字节的更高版本也会拒绝。过去签发的许可保留回执身份，回读显示其当前是否仍可执行。

来源回收是单独 `source.cleanup` 能力，由可信执行器持有；服务签发短期、逐输入、逐凭据租约的许可，实际源文件提供方负责原子回收和本地恢复日志。服务只接受明确结果回执，不把许可发放当作文件已清理。较新租约可补写同执行器已发生的结果，不能拿旧许可开始新副作用。模型无回执写工具；无可靠回收能力的来源保持原状。恢复到新实例会撤销未决许可，历史保护只作为记录，必须重新建立本实例的独立保护。

旧 v2 数据仅允许在隔离副本执行一次性迁移演练；资产身份、事件集合、标签空集合、人工来源和内容摘要均须核对。当前不能把新库基础结构或备份清单宣称为完成迁移；真实切换需独立迁移与回退证据。
