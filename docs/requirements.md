# 产品要求

本文件是 Next 产品行为的权威入口。来源为 2026-11-13 讨论中 R01–R23，以及 11-14 至 11-17 用户确认的实用优化和本次授权。旧讨论的“尚未授权实施”已被 11-17 的独立仓库重构授权取代；旧实现不构成新实现模板。用户要求独立完善计划，旧 AI 自行增加的架构/补丁不自动继承。代码与验证状态见 [当前状态](status.md)。

## 运行形态与范围

| 编号 | 必须达到的行为 |
|---|---|
| R01 | PC 先承载后端，最终 NAS 为唯一业务核心。Android/Web 通过同一 API 访问，不设手机独立业务库。服务离线准确展示，不伪报管理成功。 |
| R02 | 保留浏览、搜索、预览、播放、详情管理、批量上传、系统分享、分片续传和失败重试。普通上传不依赖 AI。 |
| R18 | 全新目录与独立 Git 历史，从空目录重新实现；旧软件继续可用。开发与验收隔离真实数据，成熟后才按迁移条件切换。 |
| R19 | 单用户、多设备；独立可撤销设备会话与 AI 凭据。无家庭账户、多租户或分库权限产品扩展。 |
| R20 | 旧版实际UI保持一致，可直接复用纯表现层代码；优化背后的状态、数据与API实现。不得自拟新页面布局、增删主导航或改变配色/字号/封面比例/操作流程。只增加已同意的Telegram风格平滑过渡、液态玻璃导航材质与选中效果，其余视觉或交互变化需用户明确同意。 |

内容范围是图片、动图、收藏视频、组图、作者/角色及轻量 AI 短剧。暂不实现压缩包解压、全库相似画质比较、影视刮削、作者新作自动抓取、全局 NAS 助手或多人体系。组图初期逐张展示，同时保存稳定集合关系。

## 接收、研究与入库

| 编号 | 必须达到的行为 |
|---|---|
| R03 | 用户交到约定入口的文件默认作为新增；不推定替换。批次允许混合作者、作品与类型，每项均有结果。 |
| R04 | 简短意图即可按任务/状态获取能力、前置条件、政策与下一步；不用读源码或另写重复业务 Skill。已确认资料与适用证据可复用，中断后不依赖聊天记忆。 |
| R05 | 有限研究后作者仍不明的媒体正常入库，归“其他搁置”占位作者并保留未确认状态。占位不是已核实归属。入库后不主动周期研究；用户安排确认后移除占位、关联真实作者。 |
| R06 | 新提交精确重复或替换候选按适用授权处理，没有针对性授权时询问受影响项。相同操作重试回放原结果，不再当新重复提交。哈希/大小查重不冒充高清判定。 |
| R07 | 保留来源原名、相对路径与输入映射；先提取线索再核实、命名。原名和模型候选不直接成为已确认角色/出处。 |
| R08 | 盘点→原名线索→候选分组→同次看图核对角色/组图/页序→必要研究→确定性计划。相同角色、作者或数字后缀不能单独证明同组；每个输入有明确去向。 |
| R09 | 未知角色/出处只写已确认部分；保留有用原名，完全无意义时用中性名称。允许未知入库，保存线索，后续按用户安排补全。 |
| R10 | 已授权范围内的正常新增自动完成研究、命名、关联与入库，最终汇报。重复、冲突、未授权替换仅暂停相关项，其余继续。确认字段或模型声明不能扩大实际权限。 |
| R12 | App 默认普通上传；智能整理显式选择。执行器离线/未配置/缺外传许可时准确等待，不假称研究失败后静默降级。 |
| R13 | 组图逐张浏览，保存集合身份与页序；以后聚合展示不靠解析文件名重建唯一真相。 |
| R14 | 短剧以集合名、连续编号与用户备注管理。明确简称/ID可复用，多匹配才询问；不为备注额外分析视频，不自动改写备注。默认追加，替换需明确目标。 |

外部研究与业务写入分开：图片、视频可在没有作者名提示时开始只读研究；候选、作品原帖、证据等级、排除与未解决条件分别保存。来源页、转载、水印或搜索摘要不能自称已验证作者。作者档案可复用，但不能替代新媒体归属证据。外传权限由可信配置控制。

## 命名与当前实用规则（R07/R08/R22）

- 编号作用域包含实例、库/目录、命名族与媒体类别；图片及动图归图片编号序列，视频单独序列，同类不同扩展名共用序列。媒体展示分类仍区分动图。
- 先确认作品分组，再分配作品编号，最后生成页码。一组只占一个作品编号，组图页固定 `({页码})` 半角圆括号。
- 新作品优先补该作用域的最小空号，无空号才最大值加一。补图只追加既有最大页加一，不擅自填缺页或重排。已入库批量重编号须有具体授权，不因新建自动整理全库。
- 常规名为 `{出处}  {角色} {作品编号}.ext`，出处与角色两个半角空格，编号前一个空格；组图加 ` ({页码})`。未知部分按 R09 保留线索，不编造。
- 《死或生》文件名采用 `生或死`；多出处用 `+`，多角色用 `&`。展示规范词表与文件命名可以有明确映射，但不能各端分别猜测。
- 最终编号和冲突校验由 Go 执行，客户端/模型只提供意图。计划绑定输入、目标、类别、分组、页序、修订和授权；源或目标变化则重校验。
- 精确改名与自动编号整理分开。明确目标名不能自动追加编号掩盖冲突；坏编码替换符在发布前拒绝，合法中文正常保留。
- 本地批次目检覆盖全部条目；库级扫描资源有界。工具只申请实际要执行步骤所需权限，不因可选设备动作阻断扫描。
- 上传成功已经入库；作者关联与回读属于业务完成要求，需由统一批次用例接通，不能只写在提示文字。未知作者关联“其他搁置”。

## 身份、修改与历史

| 编号 | 必须达到的行为 |
|---|---|
| R17 | 明确替换保留资产 ID、作者/标签/收藏/历史/备注。推进内容版本并失效派生缓存。新内容提交核验后删除确认的旧文件对象，不能用同路径误删新版。旧版清理失败单列，不重新替换。 |
| R21 | 保存人工修改、清空和移除的意图及修订；扫描、AI和迟到结果不能反盖。字段分开维护，缺头像不触发全量研究；别名在明确作用域唯一匹配时复用，不取首条猜身份。 |
| R23 | 多端标签改同一权威数据；明确空集合与删除有效。旧整组写入需基础修订，不凭壁钟/导出时间覆盖；重放不刷新修改时间。迁移时未知/相同时间冲突保留证据，不能把并集冒充最新状态。 |

行为事件拥有稳定幂等身份。推荐、统计、排名与浏览计数的已确认公式和日期口径需要逐项核对，不能以简单替代算法冒充既有能力。内容替换后旧时间轴/进度保留其内容版本来源，无法对应的标记明确提示，不伪造映射或静默删除。

## 持久任务、备份与来源清理

| 编号 | 必须达到的行为 |
|---|---|
| R11/R16 | 本批新内容入库核验，且覆盖实际内容版本和业务快照的独立备份确认成功后，才允许来源端移入回收站。来源不支持回收/只读/离线时保留并报告。RAID或最近一次全局备份时间不是本批凭据。 |
| R22 | 统一 API 串联接收、分析、命名、提交、关联、回读和后处理；每项从原始意图清单对账，不能以实际传输清单自证无遗漏。 |

任务权威状态与接受的计划/证据持久保存在服务端可访问的位置。租约过期拒绝旧执行器提交。副作用成功但回执丢失时，按原操作身份回读，不换 ID 盲重传。处理、备份、来源清理与报告通知分别记录；已入库待备份仍可浏览，通知失败不重跑业务。

AI 发现默认完整标准 MCP 清单以兼容不刷新列表的宿主；可验证的按需发现只是可选优化。默认模型结果有总字节上限、查询分页、显式省略和续读，完整计划以可信引用执行。任务调用/研究/时间与重复无进展有界；模型 token/费用没有宿主遥测就标未测。可信端恢复/续期保留既有消费记录。

## 本次新增执行要求

- AI日常工作流已确认：首次配置允许操作范围，此后直接在Codex/ZCode聊天中创建/接续任务，日常新增和授权资料维护不要求每次切回App。服务端持久授权决定可用库、动作、资料字段与预算；可随时撤销，派生任务不能自行扩大范围。重复、冲突、未授权替换仍单独处理。
- MCP面向通用宿主，包括Pi、Hermes、Codex/ZCode；业务不依赖宿主私有UI或工具加载机制。标准发现、文本与结构化结果、图片、错误和长结果续读须分别验证，协议兼容不能冒称所有宿主/模型效果完全一致。
- 确定规则由Go业务用例执行，不把目录扫描、最大编号推算、重名规避和事务恢复转交AI。手动作品输入的补全与续号、AI计划使用同一命名/集合规则；AI提供意图及不确定证据，后端给出可核对结果。权限依可信执行器和服务端规则的交集，模型自述不能扩大任何一层的权限。

- 业务全新实现，不复制旧业务代码；UI按最新授权可直接复用旧纯表现层并优化背后实现。性能优化必须说明真实场景及行为守恒证据。
- 编译、代码生成、一切测试、文档检查与发布构建全部在云端。
- 新旧项目可用同一套重新编写的视觉/动效组件；共享的是独立组件和规范，业务适配各自明确。回迁旧项目不得借机更换其业务规则或真实数据。
- 工程、使用、运行、AI接入、故障恢复与迁移文档清晰有入口；缺口如实登记，禁止以说明文件代替已实现链路。
