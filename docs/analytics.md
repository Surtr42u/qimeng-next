# 推荐、排行与浏览回顾

公式来自已确认产品行为，纯规则重新编写在 `server/internal/analytics`；SQL装载、偏好与快照在应用层，客户端只消费权威结果。未复制旧算法实现、缓存框架或历史性能承诺。

## 推荐

八项初始权重分别为标签相关性0.22、标签合集0.15、互动0.10、浏览时效0.15、点赞0.05、发现0.20、新鲜度0.05、浏览深度0.03。它们合计0.95；确定性随机项与每日展示扣分另算。

- 标签频次按已浏览文件出现次数，相关性取当前资产标签的归一化平均；没有偏好时默认0.2。Top20偏好与资产标签求Jaccard，没有偏好时默认0.15。
- 互动、点赞、停留时长分别按候选最大值归一化。浏览时效以1/3/7/30天分段为1/.8/.5/.2/0，从未浏览为.3；新鲜度对应1/.7/.4/.2/0。
- 发现度为 `1-min(viewCount/5,1)`；随机为稳定资产键哈希xor seed的低16位除65535乘maxRandom；今日每次已展示扣0.8。
- 无标签时回收标签两项权重，发现/随机各分一半；无点赞时将点赞权重给新鲜度；无历史时将互动权重给发现。
- 同分邻近桶以首项最高分为锚，0.05范围内确定性洗牌；图片/视频按剩余数量比例混合。同seed、输入和评分时间可复现。
- 四个预设是均衡、熟悉、探索、新鲜。修改带修订，过期表单不能覆盖新设置。

同一分区、类型、seed、权重修订、日界和目录代次共享最多 60 秒的推荐顺序。全实例最多保存 32 个顺序、共 100000 个资产 ID。超出预算的大库仍对全部候选评分，游标绑定原始条件和到期时间，后续页重新计算；此时客户端按资产 ID 去重。达到容量时优先淘汰最久未用的顺序，访问不会延长有效期。启动时为普通流的两个默认 seed 预热，预热不增加展示次数。

每次翻页只批量读取该页仍有资格的作品，并对实际返回项记录当日展示。库停用、作品变更或权重修改会使原游标返回 `recommendation_expired`，可刷新首页。评分期间可以继续其他业务写入，旧计算无法成为新代次的顺序。手机、NAS 的真实响应时间需分别测量。

## 事件与排行

事件只追加，eventId重放校验载荷；同资产、同浏览会话、同日的view/play只计一次。连续可见停留分段上报dwell，少于1秒不记，服务端向零截为整数秒。页面隐藏不计时。进度与浏览次数分开，旧内容版本不能反盖新版进度。

用户在另一台设备按下播放，只追加播放事实。Go 仅用带有明确 `positionMs` 的 `progress` 事件更新该内容版本的续播点，0 毫秒表示主动回到开头。回读详情时再组装续播、作者、收藏和标签。

每日点赞一行、累计永久保留；收藏与作者关注为布尔。排行热度为指定窗口内view+play+点赞，非总榜只纳入有窗口活动的资产，同分按原文件修改时间降序再稳定ID。排行和个性化推荐分开。

## 统计与回顾

原始事件及点赞是真相，按资产/日和小时的投影在同事务更新，可由原始记录重建。全局历史总量保留永久删除资产的活动；当前库存、分类和浏览回顾限定现存资产，这两个维度不能互相反推。

窗口按服务端明确时区计算。7/30/90天包含今日；week为12个周一对齐周，month为24个自然月，quarter为8个自然季，year为5个自然年。全部趋势从最早活动到当前，按跨度选择周/月/季，单周期补前导零桶；零活动明确空态。

回顾区分首次与再次浏览、不同资产、活跃天数和24小时停留类型。上期为相邻等长窗口，两期均有浏览才比较作者/标签份额；一次浏览可计入多个关联作者/标签，份额不宣称互斥。变化用百分点，最多六项，详情保留两期次数。

常看作者、标签和文件按同一窗口的浏览次数排序，同分按稳定身份；文件另可按停留秒数排序，无该指标活动不入榜。先按文件聚合再展开关联，多作者作品对各关联作者完整计数。停用库仍属于历史统计范围，回收站和已删除文件不进入实体榜单。榜单使用与查询条件绑定的键集游标；持续发生浏览时允许实时排序变化，刷新重新开始。

趋势响应一次返回共同日期轴上的类型与常规/COS分区值。新库强制已确认作者类别与库类别一致，未知作者可共用占位身份；因此分区以库类别为准，避免将COS库中的未知作者错误归常规。旧库跨类别关联在迁移中作为显式冲突保留证据。

接口在 [OpenAPI](../api/openapi.yaml)，实现及验证状态在 [当前状态](status.md)。
