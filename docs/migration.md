# 迁移与回退

Next 使用新数据库与新媒体测试根，不直接打开或升级旧项目运行库。开发期间不双写真实库。旧 PC 与手机各自的 v2 导出只在获准的隔离副本演练中消费，不能复制旧库然后宣布迁移成功。

## 迁移清单

核对原件内容与身份、作者普通/COS身份、档案/头像/证据、资产关联、标签空集合与删除、收藏/点赞、浏览事件幂等身份、legacy无键事件、播放进度/时间轴、备注、来源时间及集合页序。文件名、路径和总数不能作为唯一身份或成功证据；歧义进入报告，不固定取首个同名对象。

步骤按扫描清单→只读计划→隔离导入→逐项回读→恢复演练推进。不能在迁移时同时全库改名；命名整理另有明确范围。未知标签修改时间不捏造最新，冲突保留双方来源。

## 切换条件

必须有当前源码的云端门禁、目标平台产物、代表性工作流、内容/关联/历史守恒报告与可恢复备份。手机内嵌模式只在其独有数据迁出且新客户端实际可用后退役；没有在 Next 中复建它。

回退需说明切换后的新增数据如何导出/保留/迁回。保留旧程序不等于数据回退已完成。真实 NAS 与手机权限/后台行为必须独立验收；未知硬件备份能力不假定已满足来源清理条件。

本文件描述必须完成的交付条件；当前执行状态见 [状态](status.md)，未运行真实迁移。
